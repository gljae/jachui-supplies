# 자취 생활용품

세제가 언제 떨어질지 알려주는 구매 기록 앱.

**→ [gljae.github.io/jachui-supplies](https://gljae.github.io/jachui-supplies/)**

<br>

세제를 몇 번이나 다 쓰고 나서야 사러 나갔다면, 문제는 기억력이 아니라 기록이 없다는 것이다.
이 앱은 산 날짜와 "다 썼음"을 누른 날짜만 받아서 **다음에 언제 떨어질지**를 계산한다.

|  |  |
|---|---|
| **소진 예측** | 실제로 하나를 다 쓰는 데 걸린 날들의 평균으로 다음 소진일을 추정한다 |
| **단위당 단가** | 3L 18,000원과 500ml 4,500원 중 뭐가 싼지 바로 보여준다 |
| **용량당 주기** | "1개당 30일"과 "1L당 10일"을 토글로 오간다. 다음엔 몇 L짜리를 살지 정할 때 쓴다 |
| **영수증** | 사진을 붙이면 1200px로 줄이고 압축해 저장한다 |
| **통계** | 이번 달 지출, 타입·카테고리별 비중, 최근 6개월 추이 |
| **백업** | JSON으로 내보내고 되돌린다. 영수증도 함께 담을 수 있다 |

## 데이터는 어디 있나

**전부 당신의 브라우저 안에만 있다.** 서버가 없고, 계정도 없고, 아무것도 밖으로 나가지 않는다.

그래서 좋기도 하고 위험하기도 하다 — 브라우저가 저장소를 비우면 그대로 사라진다.

- **iOS 사파리**는 홈 화면에 추가하지 않은 사이트를 **7일간 방문이 없으면 통째로 지운다**
- **안드로이드 크롬**은 기기 저장 공간이 부족할 때 오래 안 쓴 사이트부터 지운다
- 인앱 브라우저(카카오톡 등)는 저장소가 앱마다 따로라 "데이터가 사라진 것처럼" 보인다

**홈 화면에 추가하면 대부분 해결된다.** 설정 화면이 현재 상태를 알려주고 추가하는 방법도 안내한다.
그래도 가끔은 설정 → 내보내기로 백업해 두는 게 좋다.

## 소진일을 어떻게 계산하나

이 앱에서 유일하게 까다로운 부분이다.

구매와 소진을 시간순 이벤트로 펼쳐 **재고 곡선**을 만든 뒤, 지금 쓰고 있는 하나를 언제 개봉했는지 찾는다.

```
개봉 시점 = max(마지막 소진일, 재고가 0에서 양수로 바뀐 마지막 날)
예상 소진일 = 개봉 시점 + 1개당 평균 사용 일수
```

"마지막 소진일"만 보면 안 된다. 다 쓰고 몇 달 뒤에 새로 산 경우 기준이 옛날 소진일에 묶여
"95일 지남"처럼 표시된다. 반대로 "최근 구매일"만 봐도 안 된다. 재고가 남은 상태에서 하나 더
사면 개봉 시점이 잘못 리셋된다. 두 조건을 함께 봐야 맞다.

용량당 주기도 함정이 있다. **표본마다 먼저 나눈 뒤 평균**을 내야 한다.

```
3L를 30일에, 1L를 15일에 썼다면
  맞음:  mean(30÷3, 15÷1) = 12.5일/L
  틀림:  (30+15) ÷ (3+1)  = 11.25일/L   ← 큰 용량에 가중치가 쏠린다
```

계산은 전부 [`src/lib/calc.ts`](src/lib/calc.ts)에 순수 함수로 있고 `new Date()`를 부르지 않는다.
오늘 날짜를 인자로 받으므로 테스트가 실행 시각에 흔들리지 않는다.

## 만들기

```bash
npm install
npm run dev
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm test` | 계산·필터·백업 로직 테스트 (112개) |
| `npm run build` | 타입 검사 + 프로덕션 빌드 |
| `npm run preview` | 빌드 결과를 띄운다. 서비스 워커를 확인하려면 여기서 |
| `npm run icons` | PWA 아이콘 PNG 재생성 |
| `npm run lint` | oxlint |

`main`에 푸시하면 테스트를 통과한 뒤 GitHub Pages로 자동 배포된다.

## 구조

```
src/
  lib/          계산·저장소·포맷 — UI를 모르는 코드만
    calc.ts       주기·소진일·단가 (순수 함수, 테스트 대상)
    units.ts      단위 환산과 혼재 판정
    db.ts         IndexedDB CRUD, 트랜잭션, 저장소 영속화
    receipt.ts    이미지 리사이즈·압축 파이프라인
    backup.ts     내보내기/가져오기 검증과 id 재매핑
    filters.ts    검색·필터·정렬 (URL 상태 포함)
    stats.ts      집계
  state/        DataContext, useToday, useInstall
  components/   재사용 UI
  pages/        Home, ItemDetail, Stats, Settings
```

로컬 저장소는 IndexedDB를 쓴다. localStorage는 5MB 제한이라 영수증 이미지를 감당하지 못하고,
IndexedDB는 Blob을 그대로 담을 수 있어 base64 오버헤드(약 33%)도 없다.

라우터는 `HashRouter`다. 정적 호스팅에서 새로고침이 깨지지 않고, 서비스 워커의 폴백도
`index.html` 하나로 끝난다.
